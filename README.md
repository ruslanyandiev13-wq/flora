# Голландия → 1С: автоматизация обработки инвойсов

Прототип веб-приложения, которое:
1. Разбирает PDF-инвойсы голландских поставщиков цветов (сейчас: шаблон MH Flowers).
2. Объединяет несколько инвойсов одной поставки в единую таблицу со сквозной нумерацией коробок.
3. Считает логистику (по коду тары × вместимости на палете × стоимости палеты).
4. Получает курс с ligovka.ru («продажа», от 10 000) + 5%.
5. Генерирует .xls в формате Excel 97-2003, готовый к загрузке в 1С — структура проверена
   построчно на реальном файле бухгалтера (совпадение 142/142 строк).

## Важно проверить перед боевым использованием

1. **Курс ligovka.ru** — скрейпер (`currency.py`) не тестировался вживую (в песочнице,
   где собиралась эта версия, доступ к ligovka.ru был заблокирован на уровне сети).
   Обязательно откройте `/review` → «Получить текущий курс» после деплоя и проверьте,
   что цифры совпадают с сайтом. Если сайт поменяет вёрстку — увидите понятную ошибку
   с предложением ввести курс вручную.
2. **Шапка 1С-файла (Week/Дата/Blad, Debnr/Naam)** — в реальном файле бухгалтера эти
   поля явно скопированы из старого примера разработчика и не менялись (число 42930 в
   дате = 14.07.2017, а не 19.07.2026). Вы сказали, что реквизиты Debnr/Naam всегда
   одинаковые — они уже стоят по умолчанию в справочнике («Получатели»). Что касается
   Week/Дата/Blad — стоит один раз уточнить у 1С-специалиста, важны ли эти поля для
   импорта, или можно оставить любые (сейчас они просто заполняются текущей датой/1/1).
3. **Только один шаблон поставщика (MH Flowers)** — если появится инвойс от другого
   голландского поставщика с другой вёрсткой, парсер его не распознает и покажет
   понятную ошибку. Новый шаблон добавляется в `pdf_parser.py` (см. комментарии в файле,
   раздел TEMPLATES) — пришлите такой PDF, я разберу и добавлю.
4. **Справочник тары пуст при первом запуске** — зайдите в «Справочники» и внесите
   коды тары (AAA, PPS, PBS, BOD, 9999, 612, 614, ...) с вместимостью на палете и
   стоимость палеты, иначе логистика не посчитается (появится понятное предупреждение).

## Запуск локально (для проверки)

```bash
python3 -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt
python3 app.py
```

Откройте http://127.0.0.1:5000

## Деплой на ваш домен/хостинг

Это обычное Flask-приложение, вариантов деплоя много, самый простой:

1. Возьмите любой VPS (или хостинг с поддержкой Python) с белым IP и доменом.
2. Установите Python 3.11+, `pip install -r requirements.txt gunicorn`.
3. Запускайте не через `python3 app.py` (это dev-сервер), а через:
   ```bash
   gunicorn -w 2 -b 0.0.0.0:8000 app:app
   ```
4. Настройте Nginx как reverse-proxy на 8000 порт + SSL (Let's Encrypt/certbot) для
   доступа по https с двух разных устройств.
5. Замените `app.secret_key` в `app.py` на случайную строку через переменную окружения
   `FLASK_SECRET_KEY` (не храните секрет в коде).
6. **База данных**: сейчас справочники (тара, палета, получатели) хранятся в
   `data/app.db` (SQLite) — при деплое убедитесь, что папка `data/` монтируется
   на постоянный диск (не теряется при обновлении/рестарте контейнера).
7. **Аутентификация**: в этом прототипе нет логина. Для реального использования двумя
   сотрудниками нужно добавить простую авторизацию (Flask-Login + пароли, либо базовый
   HTTP-auth через Nginx) — могу добавить отдельным шагом.

## Модуль импортных инвойсов (не-Голландия) — какие накладные загружать

Отдельный раздел `/import` (параллельно голландскому, см. `import_app.py`) разбирает
инвойсы от неголландских ферм (Эквадор, Колумбия, Кения и т.д.) и собирает их в один
файл-факtуру по метке (mark).

**Поддерживаемые поставщики (11, каждый проверен на реальных инвойсах):**
Matiz Roses, Gardaexport S.A., Florsani, Rosas del Corazon (Saftec), Monterosas
(два разных макета), TESSA CORP, Astoria Export (только .xls), Rosaprima
International, CeresFarms, Utopia Farms, Star Roses (EL CAMPANARIO DE SANTA
ANITA SCC, staroses.com).

**Что можно грузить:**
- PDF-накладные от любого из 11 поставщиков выше — в любом сочетании и любом
  количестве за раз.
- **Авианакладную (AWB)** — вместе с инвойсами. Из неё автоматически берутся вес,
  ставка за кг и число мест по каждой метке (раньше это вводилось вручную).
  Вес партии делится между метками пропорционально числу мест.
- Итоговый файл выгружается либо единым «Invoice total» на всю партию (все метки
  одной таблицей, метка — отдельной колонкой), либо отдельно по каждой метке.
- .xls/.xlsx — пока понимается только формат Astoria Export. Другой .xls
  (например, встретился `INV-8891.xls` от неизвестного поставщика) даст понятную
  ошибку «не удалось распознать шаблон», а не тихо сломается или даст неверные цифры.
- PDF от поставщика, которого нет в списке выше (в т.ч. "star roses" — упоминается в
  файлах бухгалтера, но живого образца инвойса пока не было) — тоже даст понятную
  ошибку, а не догадку. Пришлите такой файл — добавлю шаблон.

**Что пока только руками:**
- Вес отправления и ставка за кг (AWB/HAWB) — реального PDF авианакладной для
  автоматического разбора ещё нет (только фото), поэтому на странице `/import/factura`
  это вводится вручную на каждую метку.
- Метки FARM/PRODUCT в выгружаемом .xls для Rosaprima/CeresFarms/Utopia Farms —
  не подтверждены реальным примером факtуры (для остальных 7 поставщиков — подтверждены).

## Структура проекта

```
app.py              - маршруты Flask (upload, review, generate, dictionaries)
pdf_parser.py        - разбор PDF-инвойсов (расширяемо под новые шаблоны поставщиков)
xls_writer.py         - сборка итогового .xls под 1С
review_edits.py       - ручные правки позиций перед выгрузкой (/review и /import/review)
deliveries.py         - раздел «Поставки»: раскладка коробок по рейсам по HAWB форвардера
deliveries_app.py     - страницы раздела «Поставки» (/deliveries)
transport.py          - расчёт логистики по таре
currency.py            - получение курса с ligovka.ru
db.py                  - справочники (SQLite): тара, палета, получатели
templates/             - HTML-шаблоны интерфейса
requirements.txt       - зависимости Python
```

## Раздел «Поставки» (метки Москвы)

Номер AWB в инвойсе фермы — план: коробки одного инвойса уходят разными рейсами.
Раздел `/deliveries` копит по метке инвойсы ферм и HAWB форвардера (Fresh Solutions)
и раскладывает коробки по фактическим рейсам по строкам «доля = ферма» из HAWB.
Поставка — рейсы, прилетевшие в один аэропорт в один день. По каждой поставке —
лист приёмки и Invoice total; логистика = платный вес HAWB × ставка за кг
(Эквадор / Колумбия, задаётся в «Справочниках»). Написания ферм (коды TESSA из
колонки Loc, названия из HAWB) — справочник «Фермы для поставок». Эталон проверки —
партия VIKA 21–25.09, `tests/tests/test_deliveries.py`.
